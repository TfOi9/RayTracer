## CUDA IR 说明文档

#### 概述
本文档描述了把 CPU 构建的场景转化为 GPU 可读的数据链路的中间表示。中间表示需要去除所有 `Trait` 和智能指针，把各个 `Material` 和 `Texture` 转化为直接可读的具体类型并列成线性表，同时拍平 `BVH` 树。IR 暂时由 `.ir` 文件存储，由 Rust 前端创建，CUDA 后端读取。

#### Texture
Texture 段开始前，先出现 Header 行：
```
TEXTURE
SIZE = ...
```
其中，`...` 处是纹理数目 `n`。
随后 `n` 行，每行 11 个数，第一个为类型编号（1 - 单色，2 - 棋盘，3 - 图片，4 - Perlin），接下来 9 个为三个 Texture 向量参数，最后为资源编号。

Texture 三个向量参数的约定如下：
- 单色（type=1）：`c1` 为颜色；`c2/c3` 占位为 0。
- 棋盘（type=2）：`c1`/`c2` 为两种颜色；`c3.x` 为 `inv_scale`；`c3.y/c3.z` 占位。
- 图片（type=3）：`c1/c2/c3` 全占位为 0；`resource_id` 指向 Resource 段对应图片。
- Perlin（type=4）：`c3.x` 为 `scale`；其余字段占位为 0。

#### Material
Material 段开始前，先出现 Header 行：
```
MATERIAL
SIZE = ...
```
其中，`...` 处是材质数目 `n`。
随后 `n` 行，每行 7 个数，第一个为类型编号，第二个为纹理编号，随后三个是颜色参数，最后两个为额外参数。

当前已注册材质类型编号：
- 1 - 漫反射（Lambertian）：`texture_id` 有效，`color/p1/p2` 占位。
- 2 - 金属（Metal）：`color` 有效，`p1=fuzz`，`texture_id` 占位。
- 3 - 透射（Dielectric）：`p1=refractive_index`，其余占位。
- 4 - 发光（DiffuseLight）：`texture_id` 有效，其他占位。
- 5 - 各向同性（Isotropic）：`texture_id` 有效，其他占位。

#### Hittable
Hittable 段开始前，先出现 Header 行：
```
HITTABLE
SIZE = ...
```
其中，`...` 处是对象数目 `n`。
随后 `n` 行，每行 22 个数，第一个为类型编号（1 - 球体，2 - 三角形，3 - 四边形，4 - 球边界常密度介质），随后 18 个 为 6 个向量的各个参数，第一个向量代表图形原点（球体/介质球 - 球心，三角形、四边形 - 一个顶点），后两个代表边向量（球体/介质球 - 占位符；三角形和四边形 - 两个邻边的向量），第四个代表移动向量，最后两个是辅助向量（对于四边形，第五个向量是 `w` 字段；对于介质球，第五个向量的 `x` 分量为 `neg_inv_density`）；随后三个参数，第一个为球体半径（对球体与介质球有效），后两个表示材质（Texture）编号和质地（Material）编号（编号即为在对应段中出现的次序，从 0 开始编号）。

#### BVH
BVH 段开始前，先出现 Header 行：
```
BVH
SIZE = ...
```
其中，`...` 处是对象数目 `n`。
随后 `n` 行，每行 9 个数，前两个为当前节点的左右孩子编号（若无，使用 -1 占位），随后六个表示当前节点的包围盒，依次是 x 最小值、x 最大值、y 最小值、y 最大值、z 最小值和 z 最大值。最后为节点对应的对象编号（仅对叶子节点有效，否则为 -1 占位）。

#### Resource
Resource 段开始前，先出现 Header 行：
```
RESOURCE
SIZE = ...
```
其中，`...` 处是资源数目 `n`。

Resource 段采用“头 + 负载”格式。对每个资源，先写一行资源头，随后写负载行。

当前资源类型：
- 1 - 图片

图片资源格式：
```text
1 <width> <height>
<r0> <g0> <b0>
<r1> <g1> <b1>
...
```
即资源头后紧跟 `width * height` 行像素数据，按行优先顺序（`y` 从上到下、每行 `x` 从左到右）展开。像素值为 Rust 端解析后的线性 RGB 浮点值。

注意：IR 不再存图片路径；CUDA 后端直接从 IR 读取像素池并采样。
